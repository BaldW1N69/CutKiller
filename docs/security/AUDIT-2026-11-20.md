# Security audit — 2026-11-20

Scope: the whole repository (TypeScript packages, Python workers, Studio, MCP server, Docker image, CI), for two uses: one person's own machine, and a **shared service** where others send media, EDLs or agent requests.

## Threat model

| Asset | Adversary | Entry point |
|---|---|---|
| Files of the machine (other users' media, keys, `.env`) | A user of the service, an agent driven by a hostile prompt | MCP arguments, EDL source paths, crafted media files |
| The machine's network, cloud metadata | Same, or a hostile third-party API answer | Download URLs (Openverse, Wikimedia, Pexels) |
| CPU, memory, disk | Same | EDL output settings and lengths, downloads |
| Transcripts and videos in Studio | Any website the user visits while Studio runs | Browser requests to `localhost` (CSRF, DNS rebinding) |
| The supply chain | A compromised or stale package index | Python dependency resolution |

## Findings

| # | Severity | Finding | Status |
|---|---|---|---|
| 1 | CRITICAL (shared) | MCP tools took any path: `read_edl` returned the content of any file, `write_edl` wrote anywhere | Fixed: `CUTKILLER_WORKSPACE` confinement (realpath, `..`, symlinks), `read_edl` returns only a valid EDL, `write_edl` only `.json` |
| 2 | HIGH | FFmpeg opened any format and protocol. **Proof**: a `.m3u8` sent as a rush made FFmpeg render another file of the machine | Fixed: `-protocol_whitelist file,pipe` + `-format_whitelist` (self-contained formats) on every media input, TS and Python. Regression tests in `packages/media/test/guard.test.ts`, `workers/tests/test_media_guard.py` |
| 3 | HIGH | `zod` 4.6.5: memory exhaustion validating oversized collections (validates untrusted EDLs) | Fixed: 4.6.6; `pnpm audit --prod` in CI |
| 4 | HIGH (exposed) / MEDIUM (local) | Studio: no authentication, no Host or Origin check → CSRF and DNS rebinding | Fixed: session key (link → HttpOnly SameSite=Strict cookie, or `X-CutKiller-Token`), Host allow-list, same-origin JSON-only render API, 413 over 1 MB. Tested with forged requests |
| 5 | MEDIUM | No bound on EDL output size, frame rate, bitrate, length or collections; downloads unbounded | Fixed: `LIMITS` in the EDL schema and validator (`edl.too-long`), 100 MB cap on music |
| 6 | MEDIUM | Docker image ran as root | Fixed: user `cutkiller` (uid 10001), `UV_NO_SYNC=1`; CI checks the uid |
| 7 | MEDIUM | Python: urllib3 1.26.13, requests 2.28.1, certifi 2022, idna 3.4 — **root cause**: the PyTorch index served every package it mirrors, not only torch | Fixed: explicit index for torch/torchaudio only, dependencies upgraded, `pip-audit` clean and in CI |
| 8 | LOW | Download URLs from third-party APIs went to `fetch`/FFmpeg unchecked; extension from the API in the file name | Fixed: https only, public addresses only (DNS checked), every redirect re-checked, FFmpeg `https,tls,tcp,crypto` only, extension allow-list |
| 9 | LOW | Models downloaded without a pinned revision; GitHub Actions pinned by tag | Open (YuNet is SHA-256 checked) |
| 10 | LOW | Dev-only: vite / postcss advisories (test runner, never shipped) | Open, no runtime exposure |

Verified sound: every external process is spawned with an argument list (no shell); Studio listens on 127.0.0.1 and refuses path traversal; FCP7 XML escapes text; the Studio page writes text with `textContent`; no secret in the code, logs or history; the Docker image is never pushed from a pull request; YAML is parsed with a safe parser.

## Not covered by code

Before opening CutKiller to the public: one container per job with no network and CPU/memory limits (the only barrier against an unknown decoder flaw), Studio behind your own authentication and TLS, FFmpeg kept up to date.
